# Accepted non-regression obligations

These are review obligations distilled from accepted M01/M02/M03.1 work, not new behavior requirements or permission to extend scope. Use the assigned contract and approved decisions for details; a specific approved change is not overridden by inference from this summary. [STATUS](STATUS.md) identifies revisions and evidence boundaries.

| Obligation | Traceable contract/evidence |
| --- | --- |
| **Typing focus stays with the user's application.** No keyboard grabs, SetInputFocus, activation messages, global key listener or unexpected workspace switch. Host acceptance requires actual typing, not only active-window metadata. | [M03 non-regressions](DesktopRoomie-A00-M03-placement-recovery-host-selection.md#2-non-regression-invariants-for-every-m03-mission); [M03.1 L01/L09](../experiments/desktop-probe/ACCEPTANCE-M03.1.md#owner-real-host-instructions). |
| **One pointer owner and explicit release debt.** Successful explicit acquisition establishes capture; denial must not create a gesture/menu owner. Unknown acquisition or failed release retains a cleanup obligation. Automatic opening-right capture has a distinct normal completion. Cancel neutrally; body and popup ownership never coexist. | [M02 contract](DesktopRoomie-A00-M02-dragging-and-release.md); [M02 integrated mechanisms and T16/T23](../experiments/desktop-probe/ACCEPTANCE-M02.md). |
| **Transparent/noninteractive regions remain click-through.** The translucent patch remains intentionally interactive. Popup outside dismissal consumes its gesture without click replay; popup input cannot become a body action. | [M01 checklist](../experiments/desktop-probe/ACCEPTANCE.md#acceptance-checklist-matrix); [M02 T02/T18–T20](../experiments/desktop-probe/ACCEPTANCE-M02.md#owner-integrated-t01t26-matrix). |
| **Cleanup is checked and honest.** Release before destruction; attempt remaining cleanup after failures and preserve the original fatal error. Acknowledged cleanup is idempotent; unconfirmed resource destruction is not silently successful or blindly repeated. | [M02 controlled failure evidence](../experiments/desktop-probe/ACCEPTANCE-M02.md#controlled-failure-evidence); [resource owner](../experiments/desktop-probe/src/x11/resource.rs). |
| **Coordinates and bounds remain explicit and checked.** Root pointer/body coordinates differ from local hit coordinates. Preserve grab offset, fixed-canvas fit, arithmetic/wire-range checks and live geometry truth. Reject malformed, empty, overflowing or too-small usable areas. | [M02 coordinate contract](DesktopRoomie-A00-M02-dragging-and-release.md#4-coordinates-and-valid-space); [M02 T08/T22](../experiments/desktop-probe/ACCEPTANCE-M02.md). |
| **Selected-monitor identity is stable.** Refresh the startup-selected name atom even if primary changes. Removal is an error, not migration; only absent workarea permits the documented fallback. | [M02.5 explanation](../experiments/desktop-probe/M02.5-IMPLEMENTATION.md#changes-and-decisions); [M02 T22](../experiments/desktop-probe/ACCEPTANCE-M02.md#controlled-failure-evidence). |
| **Cooperate with the managed WM and report observed truth.** Request acknowledgement alone proves neither geometry nor layer success. Distinguish desired, requested, confirmed and last readable state; contradictory/unreadable state is not success. Do not implement fullscreen surveillance or re-raise/restack loops. | [M03.1 contract](DesktopRoomie-A00-M03-placement-recovery-host-selection.md#4-m031--presentation-layers-and-fullscreen-implementation-contract); [M03.1 state/protocol rationale](../experiments/desktop-probe/M03.1-IMPLEMENTATION.md). |
| **Asynchronous operations are finite.** No unbounded retries or WM fighting. Layer phases share one fixed deadline, final fresh read and no mutation at expiry; notifications and later pointer ownership cannot extend/stall it. Do not imply a hard timeout on synchronous transport. | [M03.1 deadline handling](../experiments/desktop-probe/M03.1-IMPLEMENTATION.md#deadline-interaction-and-failure-handling); [M03.1 controlled evidence](../experiments/desktop-probe/ACCEPTANCE-M03.1.md#controlled--injected-evidence). |
| **Idle remains event-driven.** Wait on events and active deadlines; no permanent idle button/active-window polling. Held-button safety observation is conditional, not an idle service. | [M02 T25](../experiments/desktop-probe/ACCEPTANCE-M02.md); [main event loop](../experiments/desktop-probe/src/main.rs). |
| **Interruptions cannot revive stale input.** Layout/workspace/body/popup lifecycle, expiry and errors cancel applicable interaction before teardown; suppress stale/chorded completion. Unavailable bodies defer placement/input; remap requires validation and confirmed correction. Selecting-popup obligations settle before layer dispatch; later valid input remains independent. | [M02 T21–T24](../experiments/desktop-probe/ACCEPTANCE-M02.md); [M03.1 ownership/deadlines](../experiments/desktop-probe/M03.1-IMPLEMENTATION.md#deadline-interaction-and-failure-handling). |
| **Public engine and private content stay separate.** No copyrighted NEKOPARA assets, extracted dialogue/voice, trained character models or private sensor data in the public repository. Use synthetic fixtures; third-party reuse needs approved scope and provenance/license review. | [AGENTS content/reuse rules](../AGENTS.md); [roadmap principles](DesktopRoomie-roadmap-v0.1.md#3-principles-to-preserve-as-the-design-changes). |

**Approved host-integration design policy (2026-10-09; not a newly verified runtime guarantee):** reuse mature window-manager features for optional shortcuts, launchers and session integration instead of adding a global key listener or generic daemon. The engine still owns lifecycle safety, no-focus interaction, state verification and independent CLI control. Configuration edits under the user's home directory are opt-in and documented, never silently applied. See [M03 recovery design](DesktopRoomie-A00-M03-placement-recovery-host-selection.md#5-m032--preliminary-design-boundary-not-yet-implementation-authority) and the [Openbox guide](host/OPENBOX.md).

Real-host observations, deterministic injected cases and source/CI review have different proof boundaries. Do not promote an injected failure test into a claim of physical disconnection or WM refusal acceptance. Follow [WORKFLOW](WORKFLOW.md) when recording evidence or changing a guarantee.
