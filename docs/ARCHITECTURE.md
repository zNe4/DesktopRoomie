The body is a borderless managed UTILITY window (`override_redirect=false`), with no-input hints, no WM_TAKE_FOCUS and user time zero. The popup is a short-lived override-redirect mouse surface, not a replacement host. No keyboard grab, activation request, fullscreen observer or permanent restacking policy is present.

## Event and deadline flow

Owner startup acquires and publishes Starting before any appearance delay, preventing duplicate bodies; control requests are handled during that delay. Startup validates host geometry/fit, chooses an alpha visual, constructs body/renderer, maps and verifies placement before logical interaction readiness and Ready publication. The original native input silhouette is applied during creation and reasserted after a qualifying MapNotify with an input freshness boundary. Native input is not universally disabled until startup readiness; that optional refinement was deferred. Startup observes the mapped body's layer without changing it. The loop processes bounded batches of up to 64 events, routing lifecycle/layout interruptions, fresh layer observations, popup events and body gestures; it uses one-event lookahead to avoid flushing a coalesced move across an interruption. Ordinary release flushes movement in completion order; cancellation discards pending movement first.

Stage D's visibility-transition foundations—checked empty input, pointer-release debt, gesture/menu/movement invalidation, dispatch eligibility and fresh visibility/placement predicates—are used for Hide and Show. Visibility requests cannot dispatch before settled pointer/popup obligations. Hide, including an already minimized no-op, requires the fence and fresh Iconic + Unmapped + HIDDEN confirmation. Local restoration requires Normal + Viewable + no HIDDEN, retained-monitor geometry and optional single confirmed correction before exact silhouette re-enable. An already-ready local Show is a harmless no-op; an off-workspace not-minimized body is not mapped or relocated. Minimized off-workspace Show removes HIDDEN and confirms coherent NotMinimizedElsewhere, possibly still Iconic + Unmapped, with unchanged body/current desktops and effective layer. Its qualified success has placement deferred and input unavailable; REMOVE-HIDDEN arms no post-map SHAPE synchronization. Later ordinary local return independently revalidates visibility, retained monitor, workarea and geometry/correction before exact silhouette restoration, without resurrecting Show. Body-directed stale input is filtered against the enabling sequence; ordinary placement/lifecycle events cannot reopen the fence without validation.

Workspace/current-workspace drift fails as LayoutChanged; effective-layer drift fails as LayerChanged, without compensating writes. Show preserves effective Above/Normal/Below layer, not relative peer z-order within Normal. In owner H09, Openbox raised a locally restored mapped body relative to a covering peer through its own presentation behavior; DesktopRoomie sent no MapRaised, activation or explicit stack request. This is not Bring Top.

Root coordinates drive drag targets and geometry confirmation; local coordinates drive silhouette and popup hits. Motion is coalesced before position requests. Body availability gates input: unmap/workspace interruption cancels interaction, remap requires live viewability/workspace, geometry and fit validation, and any one-shot bounds correction must be confirmed first. Destruction terminates the run and marks externally destroyed resources appropriately.

After a selecting popup's checked release and destruction, Above/Normal/Below dispatch uses fresh body/capability reads and at most one removal plus one addition. Already matching is a no-op; another selection while pending is busy. Later drag/popup ownership does not stall an existing layer operation. Relevant property notifications trigger fresh reads, not sequence-based layer confirmation. At the fixed one-second deadline there is a final fresh body observation, with no new mutation at expiry. Dismiss preserves pending layers; Quit, expiry and layout/body lifecycle abort them.

During G, visibility readiness immediately enters the same bounded layer controller; remote layer/visibility notifications cause fresh qualified observations while body ConfigureNotify remains available for ordinary movement. Local pending-layer servicing is excluded while G owns the controller. The loop checks deadlines even under sustained event traffic. The accepted Stage E correction services a new Show immediately after consumed control events in both routing sites and after the bounded batch before socket sleep; this fixed a real dual-monitor timeout where the owner waited until expiry before issuing MapWindow. Stage F retains that scheduling for both Hide and Show, including off-workspace EWMH requests. Relevant visibility notifications trigger fresh observations; requests, events and phase changes never reset deadlines, and no new mutation starts at expiry. Buffered replies/events are drained before waiting and the connection is flushed; socket `poll` uses the earliest active deadline: Hide 1000 ms, Show 2500 ms (distinct from the 4 s caller budget). Bring Top uses 3500 ms owner / 2500 ms visibility / at most 1000 ms bounded layer, with 5000 ms caller; Hide/Show callers stay 4000 ms. Movement/correction confirmation uses 150 ms. Button-safety queries use 250 ms only during active button gestures (including chord suppression); ordered observations can cancel a missed release without inventing a click or final position. Idle has no permanent safety polling. Optional duration and layer deadlines share the same wait path.

Here has one shared fatal finalizer for service and external loop errors. On a native failure, current success evidence is invalidated; a bounded read-only history round may establish actual relocation after possible dispatch; the original native error remains authoritative over later read/reply/cleanup failure, and the single owner slot clears before one reply attempt. Clean Quit/duration still result in Closing; actual selection loss remains OwnershipLost. No automatic retry, Show workaround or another owner is introduced.

Shutdown publishes Closing and settles control obligations with ordered control-endpoint cleanup. It cancels interactions and attempts pointer release before popup/renderer/body teardown and connection flush. Cleanup continues after failures; the original fatal error has priority over later cleanup errors. Explicit release records prevent fabricated success. Detailed rationale/tests remain in [M02.5](../experiments/desktop-probe/M02.5-IMPLEMENTATION.md), [M02.6](../experiments/desktop-probe/M02.6-IMPLEMENTATION.md) and [M03.1](../experiments/desktop-probe/M03.1-IMPLEMENTATION.md).

H21 confirmed truthful results across expiry and manual Quit; H26 measured no tick delta over separate visible/minimized 90-second samples; H27 documented the real Plank/Polybar representation. H23 was conditional/not exercised because Polybar IPC did not change `_NET_WORKAREA`. G3/F native gates remain historical and were not all rerun at the H SHA.

M03.3 H0 then exercised the accepted Stage-B executable with temporary owner-side source-1 `_NET_WM_DESKTOP` instrumentation. On Openbox 3.6.1/X11/Picom v13, the same managed UTILITY body moved 0→1→0 without changing the user's current desktop or typing focus; Normal/Above/Below survived; genuine HIDDEN minimization survived relocation onto the current desktop; visible relocation generated real map/unmap/WM_STATE churn while already-minimized relocation did not implicitly Show; the five-desktop workarea/zero-viewport model matched Stage B. Minimized geometry was trustworthy in that session, but this does not change the conservative deferred-correction implementation contract. On the later D4.1 executable `4c67da0b09ffe7b69605ac4a415d256acf8abd23`, the owner tested the actual public `--bring-here` command: local no-op, remote Normal/Above/Below, genuine minimized relocation for all three layers, Openbox Iconic/no-HIDDEN, actual typing continuity, popup/drag/transparent input, already-local unsafe gesture cancellation, retained monitor, eight repeat successful relocations, Hide/Show/Bring Top regressions, duplicate launch rejection, relaunch and passive idle stability. ## Deliberate absences

There is no Brain/Spine, runtime memory service, persistent simulation, cross-device abstraction, private character asset integration, autonomous motion or window-relative A01 stacking. Independent transport, Hide/Show, original-workspace Bring Top and standalone Bring Here are accepted on the exercised Openbox host. Here is **explicitly requested**: it does not automatically follow normal workspace changes, Show a genuinely minimized body, raise/force Above, focus/activate, switch the user workspace or migrate monitors. The public `--recover` command and Here→Top composition are **not implemented**; private Recover remains Unsupported. Other WMs and Wayland remain unverified. These absences do not authorize source splitting or scope expansion; the next mission must be separately approved.
