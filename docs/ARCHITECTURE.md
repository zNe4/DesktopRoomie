# Implemented architecture

This describes the Rust/x11rb probe at reviewed executable revision `174d8a92574e16768330fb3c315578b105e4b698`, accepted through M03.2 stages A–E. It is a responsibility map, not a proposed redesign. Current unaccepted Stage-F candidate `2424c8887d83d1e503caba326cd512d036639c3e` additionally enables fenced Hide through the checked ICCCM helper in `x11/visibility.rs`, with pure Hide phases in `control.rs` and runtime progression in `main.rs`; it failed off-workspace acceptance. The approved [Openbox amendment](host/OPENBOX.md#openbox-off-workspace-visibility-amendment-2026-10-10) is a future correction, not implemented behavior. [STATUS](STATUS.md) identifies acceptance; [INVARIANTS](INVARIANTS.md) gives review obligations.

The body is a borderless managed UTILITY window (`override_redirect=false`), with no-input hints, no WM_TAKE_FOCUS and user time zero. The popup is a short-lived override-redirect mouse surface, not a replacement host. No keyboard grab, activation request, fullscreen observer or permanent restacking policy is present.

## Event and deadline flow

Owner startup acquires and publishes Starting before any appearance delay, preventing duplicate bodies; control requests are handled during that delay. Startup validates host geometry/fit, chooses an alpha visual, constructs body/renderer, maps and verifies placement before logical interaction readiness and Ready publication. The original native input silhouette is applied during creation and reasserted after a qualifying MapNotify with an input freshness boundary. Native input is not universally disabled until startup readiness; that optional refinement was deferred. Startup observes the mapped body's layer without changing it. The loop processes bounded batches of up to 64 events, routing lifecycle/layout interruptions, fresh layer observations, popup events and body gestures; it uses one-event lookahead to avoid flushing a coalesced move across an interruption. Ordinary release flushes movement in completion order; cancellation discards pending movement first.

Stage D's visibility-transition foundations—checked empty input, pointer-release debt, gesture/menu/movement invalidation, dispatch eligibility and fresh visibility/placement predicates—are now used for Show. The owner never dispatches MapWindow before settled input obligations. Actual local restoration requires Normal + Viewable + no HIDDEN, retained-monitor geometry and optional single confirmed correction before exact silhouette re-enable. An already-ready local Show is a harmless no-op; an off-workspace not-minimized body is not mapped or relocated, and local placement/input stay deferred until later verified return. Body-directed stale input is filtered against the enabling sequence; ordinary placement/lifecycle events cannot reopen the fence.

Root coordinates drive drag targets and geometry confirmation; local coordinates drive silhouette and popup hits. Motion is coalesced before position requests. Body availability gates input: unmap/workspace interruption cancels interaction, remap requires live viewability/workspace, geometry and fit validation, and any one-shot bounds correction must be confirmed first. Destruction terminates the run and marks externally destroyed resources appropriately.

After a selecting popup's checked release and destruction, Above/Normal/Below dispatch uses fresh body/capability reads and at most one removal plus one addition. Already matching is a no-op; another selection while pending is busy. Later drag/popup ownership does not stall an existing layer operation. Relevant property notifications trigger fresh reads, not sequence-based layer confirmation. At the fixed one-second deadline there is a final fresh body observation, with no new mutation at expiry. Dismiss preserves pending layers; Quit, expiry and layout/body lifecycle abort them.

The loop checks deadlines even under sustained event traffic. The accepted Stage E correction services a new Show immediately after consumed control events in both routing sites and after the bounded batch before socket sleep; this fixed a real dual-monitor timeout where the owner waited until expiry before issuing MapWindow. Buffered replies/events are drained before waiting and the connection is flushed; socket `poll` uses the earliest active deadline, including Show's fixed 2500 ms owner deadline (distinct from the 4 s caller budget). Movement/correction confirmation uses 150 ms. Button-safety queries use 250 ms only during active button gestures (including chord suppression); ordered observations can cancel a missed release without inventing a click or final position. Idle has no permanent safety polling. Optional duration and layer deadlines share the same wait path.

Shutdown publishes Closing and settles control obligations with ordered control-endpoint cleanup. It cancels interactions and attempts pointer release before popup/renderer/body teardown and connection flush. Cleanup continues after failures; the original fatal error has priority over later cleanup errors. Explicit release records prevent fabricated success. Detailed rationale/tests remain in [M02.5](../experiments/desktop-probe/M02.5-IMPLEMENTATION.md), [M02.6](../experiments/desktop-probe/M02.6-IMPLEMENTATION.md) and [M03.1](../experiments/desktop-probe/M03.1-IMPLEMENTATION.md).

## Deliberate absences

There is no Brain/Spine, runtime memory service, persistent simulation, cross-device abstraction, private character asset integration, autonomous motion or window-relative A01 stacking. Independent transport and Show recovery are accepted. At the accepted Stage-E revision, Ready Hide/Bring Top return Failed / Unsupported / Preflight (exit 7); Hide is enabled in the unaccepted F candidate and requires the approved off-workspace Hide/Show correction. Remote Bring Top remains blocked at G; workspace movement belongs to later M03.3. Show does not activate, change desktop/layer or create a replacement body. These absences do not authorize interfaces, source splitting or architectural expansion; use a bounded approved mission.
