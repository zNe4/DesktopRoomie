## State and transition contract

`LayerController` owns:

- `desired: Option<Layer>`: last accepted target, initially absent; never a background policy to reassert.
- `observed: Option<ObservedLayer>`: last readable snapshot: Normal, Above, Below, or Conflict. A read failure does not overwrite this with an optimistic result; diagnostics call it the last readable state.
- `pending: Option<PendingLayer>`: AwaitRemoval or AwaitFinal, one fixed deadline, and the flags required by the complete mutation plan.

All decisions use fresh property reads. Stored observations are diagnostic history, not a confirmation shortcut.

| Target | Initial readable state | Bounded mutations |
| --- | --- | --- |
| Above | Above | No-op |
| Above | Normal | ADD Above |
| Above | Below or Conflict | REMOVE Below; after its absence is freshly confirmed, finish if already Above, otherwise ADD Above |
| Below | Below | No-op |
| Below | Normal | ADD Below |
| Below | Above or Conflict | REMOVE Above; after its absence is freshly confirmed, finish if already Below, otherwise ADD Below |
| Normal | Normal | No-op |
| Normal | Above / Below / Conflict | REMOVE the present layer flag(s); both in one message for Conflict |

Completion requires the exact target predicate. Conflict is never success. Each operation has at most one removal and one addition; unexpected state changes do not create retries. A successful removal is not rolled back if addition fails.

The entire transition's required support is checked before the first mutation and rechecked before addition. An idempotent fresh match does not query or claim mutation support. Pending work is also checked when root `_NET_SUPPORTED` changes.

## X11 protocol and decoding

Intern `_NET_SUPPORTED`, `_NET_WM_STATE`, `_NET_WM_STATE_ABOVE`, and `_NET_WM_STATE_BELOW` once for the run. Reuse existing root and body property subscriptions; do not replace their event masks.

Every mutation uses:

```text
SendEvent(propagate=false, destination=root,
          event_mask=SUBSTRUCTURE_NOTIFY | SUBSTRUCTURE_REDIRECT)
ClientMessage(window=body, type=_NET_WM_STATE, format=32,
              data=[REMOVE(0) or ADD(1), first_atom, second_atom_or_0, 1, 0])
```

`VoidCookie.check()` checks X protocol processing only. After each successful checked send, read the body state again. While pending, every relevant body `_NET_WM_STATE` PropertyNotify triggers another fresh read. Notification sequence and timestamp do not identify a WM operation and are not used to gate layer confirmation. Unrelated properties/windows are ignored by layer confirmation. A queued stale notification can cause an extra current read, never substitute its own historical meaning for that read.

`GetProperty` uses `delete=false`, `type=ANY`, offset 0 and a maximum of 4096 atoms. Present properties must be ATOM/32, complete (`bytes_after=0`), within the cap, and have consistent item/payload lengths. Unknown atoms and duplicates do not alter membership semantics.

- Present empty body ATOM/32, or a valid list without either layer flag: Normal.
- Present Above only / Below only / both: Above / Below / Conflict.
- Absent body state: unverifiable, never Normal or a confirmed removal.
- Malformed, wrong-type/format, or truncated body state: unverifiable.
- Canonical absent or empty `_NET_SUPPORTED`: no advertised support.
- Malformed support: no mutation.

Before each body property read, check that the body is viewable. This handles a queued property notification whose corresponding unmap has not yet been processed. Absence during a withdrawal race remains unverifiable even if availability changes between requests. Body lifecycle events independently abort pending work.

The implementation never directly writes managed `_NET_WM_STATE`, requests activation, changes focus, grabs the keyboard, manually restacks, or observes fullscreen state on other applications.

## Deadline, interaction, and failure handling

The total deadline is acceptance time plus one second, using `Instant`. Initial reads and capability preflight consume that same budget. Notifications, removal, addition, later input, and other events never extend it. Before a mutation, check expiry again after capability reads. At expiry make one final fresh body read: matching state completes; otherwise terminate with target, last readable state and phase. Unverifiable data reports its cause and ends pending work. Fatal protocol failures retain their original error.

The layer deadline joins the existing duration, geometry-confirmation, bounds-correction and gesture-safety deadlines. It is checked between bounded event batches. Existing buffered-event checks after synchronous X11 operations remain in place. Completion, failure, timeout and abort clear the layer timer; there is no idle layer polling. Later property changes can update observed truth but do not resurrect an old operation.

Canonical menu order is Above, Normal, Below, Dismiss, Quit. A matching layer selection first invalidates its popup interaction, performs checked release and popup destruction, then dispatches. Any cleanup failure prevents dispatch. Existing cleanup continues to attempt independent obligations and retains original-error priority.

After the first request begins, layer progression is independent of later pointer ownership. A subsequent left drag or newer popup does not defer addition, and layer notifications do not cancel those interactions. A second layer selection is busy after its selecting popup is safely cleaned up; it does not replace, queue, or cancel the original operation. Dismiss preserves pending layer work; Quit ends it.

Layout/workspace changes and body map/unmap/destroy abort pending layer work and preserve M02 cancellation/placement behavior. Duration expiry and shutdown abandon layer work before checked interaction/resource cleanup. There is no layer restoration request on exit.

Unsupported capabilities, unverifiable properties and timeouts are recoverable layer-operation failures. X11 request/check/reply/connection failures remain fatal probe errors, followed by best-effort checked cleanup. WM refusal has no separate rejection response here; an unmet predicate reaches the finite timeout.

## Verification boundaries and limitations

Deterministic tests exercise the production transition and orchestration helpers with property fixtures, fake checked-send/read outcomes and injected time. All 112 M02 test cases retain their behavioral intent; Dismiss/Quit row indices were updated and one selection test now covers all five choices. The suite contains 137 tests after adding 25 M03.1 cases.

These tests do not prove actual Openbox stacking, focus isolation on this build, compositor behavior, or real X server failure recovery. The one-second deadline bounds WM confirmation with a responsive X server; existing synchronous `.check()` and `.reply()` operations do not provide a hard transport timeout against a completely stalled server.

A late WM result can arrive after timeout. EWMH provides no operation IDs; a fresh match establishes current flags, not causality or lasting visual ordering. Below can fully cover the body, and independent recovery is deferred. Use exposed-body test placement and a finite duration during owner acceptance.

Fullscreen is exclusively L07/L08 owner observation: establish Above, close the popup, enter a normal application's actual fullscreen mode, then exit fullscreen without issuing another layer action. There is no fullscreen observer, automatic raising or restoration loop.

M03.2–M03.4, A01, relative stacking, hide/show, IPC, workspace placement, persistence, host configuration changes and architectural expansion are outside this implementation.
