## Implemented CLI contract

| Command | Guaranteed confirmation | Boundaries |
| --- | --- | --- |
| `--hide` | Safe transition fencing, checked minimization, same owner remains available. | Never a second body, no workspace movement. |
| `--show` | Genuine minimized body becomes not minimized on its existing desktop; or fresh-read already-not-minimized no-op. | Off-workspace success is qualified; never promises visibility on caller's desktop. |
| `--bring-top` | Show if necessary, then confirm exact Above using existing M03.1 absolute layer controller. | No activation, no Bring Here or Recover, no fullscreen-precedence or relative z-order promise. |

Help/Diagnose/Owner/Control are mutually checked parser modes. `--duration` and `--delay` remain owner launch options. The body is the same managed borderless 160×160 `_NET_WM_WINDOW_TYPE_UTILITY` ARGB window, using the existing silhouette and five-row right-click menu.

## Ownership, control, and lifecycle

A cooperative owner verifies an actual server timestamp and guarded selection before creating the body; Starting is public before any owner `--delay`. Duplicates do not create a second body. A separate command validates the owner and its temporary caller marker, sends a correlated private ClientMessage, and waits for a bounded terminal response. One active remote operation; concurrent conflicting requests are Busy, not queued or replayed. Admission, request sending, event delivery and terminal WM confirmation are distinct facts.

The owner integrates state progression in bounded existing X11 event batches and the earliest active deadline. No idle polling, automatic retry, replay cache or reassertion loop. Fixed **owner** deadlines: Hide 1000 ms, Show 2500 ms, Bring Top 3500 ms; Bring Top's visibility cutoff is admission +2500 ms, its layer stage up to 1000 ms within the owner deadline, and geometry confirmation 150 ms. **Caller** budgets: Hide/Show 4000 ms, Bring Top 5000 ms. Synchronous X11 delays are not hard bounded by these logical budgets.

Exit codes: 0 confirmed success/normal owner completion; 1 owner/local failure; 2 usage; 3 no instance; 4 duplicate owner; 5 Starting/Busy/Closing; 6 malformed/incompatible peer; 7 failed or unconfirmed; 8 timeout or vanished owner with unknown result; 9 confirmed Partial. A timeout or vanished owner is **not** success and does not mean no mutation occurred.

Quit/duration publish Closing before teardown, finish any active remote reply attempt, cancel layer/gesture/motion work, settle pointer and popup obligations and destroy managed resources, preserving the first error and still attempting remaining cleanup. Peer reply death is handled without building up orphan state. Native H21 validated owner disappearance and no-owner responses.

## Openbox minimized/off-workspace semantics

On Openbox, `WM_STATE Iconic + IsUnMapped` can mean merely *other desktop*; **HIDDEN** distinguishes actual minimization. Ordinary other-workspace Iconic + no HIDDEN is therefore not a reason to MapWindow, and ICCCM IconicState requests alone cannot produce genuine minimization there.

| Body context | Hide | Restore genuine HIDDEN | Already not minimized Show |
| --- | --- | --- | --- |
| Local/current/all-desktop | Checked ICCCM IconicState, confirm Iconic/Unmapped/HIDDEN. | Checked `_NET_WM_USER_TIME=0` + one MapWindow; confirm Normal/Viewable/no HIDDEN and geometry/input readiness. | Fresh-read no-op. |
| Other desktop | Checked WM-directed `_NET_WM_STATE ADD HIDDEN`, confirm genuine HIDDEN. | Checked WM-directed `REMOVE HIDDEN`, **no MapWindow or user-time write**; coherent no-HIDDEN off-workspace success, input deferred. | No presentation request; preserve desktops/geometry/layer. |

These EWMH requests are checked ClientMessages to the WM, **not** direct property writes. No code writes `_NET_WM_DESKTOP` or `_NET_CURRENT_DESKTOP` or invokes focus/activation/restack policy. The original Stage-F failed off-workspace Hide and manual failed off-workspace MapWindow Show remain explicit historical evidence; the separate correction introduced the accepted ADD/REMOVE split. Off-workspace placement/input readiness is verified only upon later natural local return.

## Input fence, geometry, and Bring Top

Before actual Hide/Show transition, the input fence disables the interactive SHAPE, cancels gestures, popup and queued/final movement, and attempts checked release for both tracked and possible automatic grabs. An unresolved release obligation blocks dispatch. Local input is restored only after fresh visibility, monitor, fit and any needed one-shot workarea correction confirmation, with original silhouette and event sequence freshness. Unavailable/off-workspace bodies defer this process; workarea of the *caller* desktop never repositions the remote body.

Bring Top reuses the same visibility readiness path and the **single** M03.1 layer controller. It removes opposing flags before adding Above; exact Above is established by fresh WM property observation, not request acknowledgement. A confirmed restore followed by failing/unconfirmed layer stage may justify truthful historical-proof Partial, but never fictitious final layer success. No relative peer order or precedence over fullscreen is guaranteed.
