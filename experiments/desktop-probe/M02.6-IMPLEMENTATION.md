## Implementation

The existing managed body remains the M02.5 body. The menu is a separate, short-lived, opaque native X11 `InputOutput` root child. It uses the root depth, visual, and colormap, sets `override_redirect`, and sets `_NET_WM_WINDOW_TYPE_POPUP_MENU` before mapping. The measured core `fixed` font draws exactly two rows: **Dismiss** and **Quit**, with a border, separator, hover highlight, and pressed-row treatment. No UI toolkit or dependency was added.

The popup does not request keyboard focus or activation. The implementation contains no `SetInputFocus`, keyboard grab, or global key handling. Pointer capture uses asynchronous keyboard mode as part of `GrabPointer`; this is not a keyboard grab.

The interaction state machine adds `RightPressed`, `MenuOpen`, and nested pending menu gestures. The pointer tracker distinguishes the existing body-left explicit grab, the server's automatic opening-right grab, and the explicit menu grab. A normal unchorded right release clears automatic-grab ownership locally; it does not send an unnecessary `UngrabPointer`. Cancellation before release explicitly ungrabs and preserves the M02.5 checked-release obligation if acknowledgement fails.

After popup setup and checked mapping, the program makes one checked `GrabPointer` request with the popup as grab window, `owner_events = false`, asynchronous pointer and keyboard modes, button/motion events, no confinement, and the matching opening-release timestamp. The menu enters `MenuOpen` only after `SUCCESS`. A denied status causes popup cleanup and returns to body interaction; a protocol or connection error remains fatal and retains the original diagnostic.

Popup placement and row hit testing are pure, deterministic helpers. Placement uses the current selected usable rectangle, tries right/below first, flips axes near edges, then clamps as a final step. It checks fit, arithmetic, and X11 coordinate limits. The popup owns its window, GC, and font resources with checked, idempotent cleanup. Capture is released before the popup window is destroyed.

The popup records its generation and creation/acquisition request sequences. Event routing checks the popup window and generation and rejects pre-acquisition or synthetic pointer events; lifecycle events are also checked against creation ordering. Popup pointer events are handled before body pointer events and cannot become body drag or click actions.

M02.5 cancellation and lifecycle handling was extended to close the popup and release its capture on duration expiry, workspace/layout changes, popup or body lifecycle changes, shutdown, and errors. Ordered button-state observations preserve opening/menu ownership during chords. Button 2 and wheel input do not act as menu commands. Outside Button 1 dismissal consumes the complete press/release gesture without replaying it.

## Owner-performed manual acceptance

The owner reports: **all requested M02.6 manual tests passed on the target Openbox/X11/Picom desktop.** The owner verified that:

- Opening, menu use, and dismissal preserved typing focus in the previously focused application.
- Placement worked near all tested corners and edges.
- Holding right did not open the menu until release; releasing the opening gesture outside the interactive body did not open it.
- Right press during a left drag cancelled without opening the menu.
- Dismiss worked. Pressing an item and releasing elsewhere did not activate it.
- An outside left click dismissed the menu while consuming that gesture; the next fresh click reached the underlying application. This also worked with the pointer on the secondary display.
- A fresh right click dismissed the menu without opening the underlying application's context menu.
- Quit cleaned up and exited normally.
- Duration expiry with the menu open, including while holding a menu item, recovered correctly.
- Workspace switching with the menu open cancelled it correctly, and M02.5 workspace behavior remained intact.
- Repeated drag/open/dismiss cycles left no orphan popup or stuck pointer capture.
- Baseline left click, drag, transparent-padding click-through, and focus behavior remained correct.

No timings, screenshots, or additional environment changes are asserted by this record.
