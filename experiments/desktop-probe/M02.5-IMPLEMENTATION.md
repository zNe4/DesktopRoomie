## Changes and decisions

- `src/main.rs`: group the existing coordinator's gesture, pending movement, safety observation, and body availability state in `ProbeRuntime`. Share cancellation between interruption, movement mismatch, duration expiry, and shutdown. Cancellation discards coalesced movement and final gesture expectations before attempting release; a failed release cannot leave a live gesture. Ordinary release still flushes pending movement before deriving its final target. A one-event lookahead preserves that distinction across the 64-event batch boundary.
- `src/interaction.rs`: share neutral cancellation and suppress late motion/releases. Fresh genuine presses can recover when the old release happened elsewhere. Temporary wrap-aware timestamp guards reject releases/motion older than a new press. The first ordered held-button observation ends the temporary guard, so timestamp age does not limit a stationary hold.
- `src/x11/pointer.rs`: sample the initiating left button with root `QueryPointer` every provisional 250 ms while captured. A held button rearms the timer; a confirmed release cancels without a click or invented final position. No safety timer remains in idle or after cancellation. Checked ungrab acknowledgement clears ownership; failed release remains an explicit obligation.
- Safety observations carry their gesture generation and the QueryPointer request's extended sequence number. Events whose last-processed request sequence precedes that request are dispatched first, including events buffered by synchronous replies and spanning multiple batches. The observation is applied before later events, or at an empty queue. A queued ordinary release retains its completion; a queued new press invalidates the old observation. This uses x11rb's existing ordering, rather than a general sequencing framework.
- `src/x11/monitors.rs`: subscribe to RandR monitor/resource/output changes and relevant root properties. Select the startup primary monitor (first active monitor if no primary is marked), retain its monitor-name atom, and record output IDs. Refresh by that atom, without migration when primary status changes. Distinguish query failure from removal, absent workarea from malformed/truncated properties, and valid intersection from empty/overflowing bounds. Only absent workarea falls back to monitor bounds, with a warning.
- Body unmap cancels and suspends input. Remap requires live VIEWABLE status, workspace verification, refreshed geometry, fixed canvas dimensions, and valid placement. Workspace changes do not request activation, remapping, or workspace movement. Placement waits while unavailable. External destruction shuts down and marks the window already released.
- Changed bounds permit one corrective placement followed by a live check at the existing 150 ms confirmation deadline. Input waits for that check. Pending correction is retained through duplicate layout notifications, so they cannot repeatedly issue it or extend its deadline. If newer bounds require a different correction, the previous one must first be verified. Necessary correction refusal terminates with a diagnostic. The existing bounded movement queue and historical notification classification remain in `src/x11/window.rs`.
- `src/x11/resource.rs`, renderer, and window: narrow ownership/cleanup helpers make acknowledged cleanup idempotent, retain unacknowledged outcomes, attempt all remaining resources after failures, and preserve the original fatal error. Release is attempted before target destruction. Partial initialization also releases previously acquired resources. After connection loss, diagnostics do not claim server cleanup or pointer release succeeded.

No new dependencies or architecture services were introduced. The existing procedural rendering, fixed input shape, managed window hints, and position-only movement remain. No M02.6 menu or M02.7 combined acceptance work was implemented. Historical `ACCEPTANCE.md`, `ENVIRONMENT.md`, roadmaps, and research documents were not edited.

## Implementation limits

The runtime requires RandR 1.5 monitor identities and supported signed X11 placement coordinates; it rejects unsupported ranges rather than wrapping them. Verified input additionally requires a valid body `_NET_WM_DESKTOP` property on the managed target; absence or malformed metadata reports unsupported verification rather than guessing workspace membership. Missing root `_NET_CURRENT_DESKTOP` uses desktop 0 with a warning.

The existing WM confirmation timeout is 150 ms. A refused necessary bounds correction intentionally exits instead of fighting the WM. A body that remains unmapped stays unavailable until verified remap. Connection loss permits only best-effort teardown; unacknowledged resource/release obligations remain explicit.
