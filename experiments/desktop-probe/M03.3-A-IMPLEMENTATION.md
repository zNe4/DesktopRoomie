## Wire representation

Private protocol `VERSION = 2`; command values are Hide 1, Show 2, Bring Top 3, Bring Here 4, Recover 5. Owner descriptors retain seven words. Caller markers require exactly eight CARDINAL words:

```text
[MAGIC, VERSION, control_xid, epoch, request_id_low, request_id_high,
 command, destination_desktop]
```

Hide/Show/Bring Top require `destination_desktop = u32::MAX` (no destination). Bring Here/Recover require any other `u32`; desktop-count validation is deferred to Stage B. The property is written once by the caller. Admission copies its destination into the single active operation, and duplicate matching includes that frozen value. Changing it cannot retarget an active operation or renew its deadline. Request and terminal ClientMessages retain five words; request ID/owner epoch correlation remains unchanged. Incompatible descriptors/markers are rejected; a v2 marker can safely correlate a WrongVersion reply for an incompatible request header, without translating v1 identities.

Existing detail bits 0–23 retain their meanings. V2 assigns:

| Bits | Meaning |
| --- | --- |
| 24 | Current destination membership and frozen destination still current |
| 25 | Historically confirmed relocation from another desktop |
| 26 | Historically confirmed restoration from genuine minimization |
| 27–28 | Geometry proof: 0 unknown, 1 admissible/deferred, 2 verified; 3 invalid |
| 29 | Currently preserved genuine minimization |
| 30 | Currently preserved effective layer |
| 31 | Reserved; rejected |

The existing placement-deferred bit 18 remains a deferral flag. Geometry proof 1 additionally proves retained-monitor/destination-area fit; it does not claim corrected actual geometry. Contradictory new wire proofs are rejected by detail decoding and terminal encoding/decoding.

## Pure state and result validation

`ActiveOperation` remains the sole operation owner. It now also contains `PlacementProgress` (frozen destination, optional original desktop/minimization/effective-layer baseline and proofs) and `RecoverPhase::{Here, Top}` (identity only). No additional controller, queue, scheduler or completed-request service exists. `Stage::Placement = 6` is added; old stage values and wire reasons are unchanged. New decode errors distinguish invalid destinations and contradictory proofs.

`PlacementProof` separates `PlacementConfirmation` from `RecoveryHistory`. Clearing current placement proof retains historical transitions; neither historical bit derives any current destination, geometry, visibility or input bit. Command-specific placement result validation checks the original baseline, current proof and terminal detail together. A sticky/all-desktop baseline cannot justify placement proof.

Bring Here Success requires current destination and preserved effective layer. Ordinary Success additionally requires confirmed local not-minimized visibility, verified geometry and input readiness, with no silent restoration of a minimized baseline. Qualified minimized Success instead requires confirmed preserved genuine minimization and disabled input, with either verified geometry or admissible/deferred geometry. The deferred case explicitly sets bit 18 and geometry proof 1.

Recover Success requires current destination, local not-minimized visibility, exact confirmed Above, verified geometry and input readiness. The corrected terminal partition is Success for complete current postconditions, Partial for incomplete postconditions with meaningful historical progress, and Failed for incomplete postconditions without meaningful historical progress. Recover Partial requires historical relocation and/or restoration from the corresponding original baseline. Bring Here Partial requires historical relocation only. No-op, geometry correction, dispatch, pre-existing readiness or phase identity alone cannot justify Partial. Historical progress cannot be discarded into Failed. Accepted Hide/Show/Bring Top validators remain separate, including Bring Top's constructor-only historical restoration rule.

| Command | Owner from admission | Caller from before discovery |
| --- | --- | --- |
| Hide | 1000 ms | 4000 ms |
| Show | 2500 ms | 4000 ms |
| Bring Top | 3500 ms | 5000 ms |
| Bring Here | 3500 ms | 5000 ms |
| Recover | 7000 ms total | 9000 ms total |

Bring Top's admission +2500 ms visibility cutoff and `min(layer admission +1000 ms, owner deadline)` remain unchanged. Recover has no running phases yet; its total deadline is allocated once at admission.

## Execution boundary and verification

CLI flags remain limited to the accepted Hide/Show/Bring Top commands. Stage A captures no destination and exposes no new desktop-number syntax. Valid incoming Bring Here/Recover v2 requests obey Starting/Closing/Busy policy, then terminate with Failed/Unsupported/Preflight directly through the transport seam, which has no body/WM/input operations. A defensive main service guard likewise returns Unsupported without calling body-host methods.

No destination reads, workspace relocation primitive, destination geometry reconciliation or Recover composition was added. Existing visibility/layer/geometry code is used only by the accepted commands. There were no dependencies or host-configuration changes.

First-candidate local verification: fmt check, build, Clippy with `--all-targets -- -D warnings`, tests (**482 passed, 0 failed**) and `git diff --check` passed. The 29 additional tests cover exact v2 codecs/destination rules, all command pairs, immutable budgets/correlation, current/history proof and lifecycle/status cross-products, qualified minimized results, invalid proof combinations, and transport/service execution boundaries. Existing tests were updated only for v2 representation/admission arguments and retained their behavioral assertions.
