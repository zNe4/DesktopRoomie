# M03.3 Stage B — destination/layout evidence

Stage B candidate; acceptance pending independent review and matching CI.

This implements only the read-only Stage-B contract from the [approved roadmap](../../docs/DesktopRoomie-A00-M03.3-staged-implementation-roadmap.md). The implementation base is `m03` / `99d56e7ffdcbb94884893a91b14d414ea3347f52`; accepted Stage-A executable/evidence remains unchanged.

## Data and native boundary

`x11::monitors::destination::query_destination_layout` accepts the retained monitor name atom, caller-frozen desktop index and fixed body `Size`. Its private `DestinationSnapshot` stores raw count/current/workarea/viewport replies and live RandR monitors. Pure validation produces `DestinationLayout`, containing desktop count/current/target, retained atom and bounds, target workarea presence/value, viewport presence/zero evidence, usable intersection, supplied size and checked `ValidOriginBounds`.

The native path uses non-deleting root `GetProperty` reads and existing RandR monitor discovery. Count/current reads request one word; workarea/viewport reads request checked count-derived word lengths. Trailing data is rejected, never paged or retried. There is no arbitrary desktop-count limit; property word and host byte lengths must be representable. Synchronous transport still assumes a responsive X server.

`LayoutAtoms` additionally interns `_NET_NUMBER_OF_DESKTOPS` and `_NET_DESKTOP_VIEWPORT`. Subscription masks are unchanged. Neither atom is integrated into existing movement, visibility or layer event handling. The destination reader has no runtime consumer in Stage B; its module-scoped dead-code allowance records that deliberate boundary.

## Strict evidence policies

- Count: genuinely present CARDINAL/32, exactly one value, positive, complete payload, exact reply metadata and no bytes after. The frozen target must differ from `u32::MAX` and be below count.
- Current: the same exact one-word CARDINAL encoding, excluding `u32::MAX`, below count and equal to the supplied target. A different valid current desktop returns `Changed`; no retargeting occurs.
- Workarea: genuine absence alone uses retained-monitor bounds. Present data must contain exactly `4 * count` words, with checked multiplication. Every advertised rectangle has positive dimensions and representable checked right/bottom edges. Only the frozen target's rectangle contributes to destination identity and intersection. CARDINAL origins preserve the existing two's-complement signed `i32` root-coordinate bit pattern; dimensions remain unsigned.
- Viewport: genuine absence is compatible and stays distinct from present data. Present data must contain exactly `2 * count` complete CARDINAL/32 words. Any nonzero coordinate on any desktop returns `UnsupportedViewport`; malformed encoding returns `Unverifiable`.
- Monitor: exactly one live monitor must match the retained name atom. Missing/ambiguous identity or zero dimensions fail. No primary fallback or migration exists. Equality uses only the retained atom and root rectangle; primary flag, display name, outputs, unrelated monitors and list ordering are excluded.
- Fit: checked monitor/target-workarea intersection must be nonempty. A positive caller-supplied body size must fit according to the existing `compute_valid_origin_bounds`. No body origin is selected, clamped, centered or dispatched.

## Agreement and failure distinctions

Two complete snapshot reads are strictly validated and their resulting placement evidence must agree. Count, current/target relation, target workarea value or presence, viewport presence, retained identity/origin/size and derived fit facts all participate. Property sequence numbers and diagnostic metadata do not. Valid non-target workarea changes do not affect target identity.

`DestinationError::{Unverifiable, UnsupportedViewport, Changed}` keeps evidence failure, unsupported virtual-desktop layout and stale/disagreeing evidence distinct without changing protocol `Reason`. Invalid/unsupported evidence never produces a layout. A native read failure returns immediately. There is no third read, retry, polling, deadline loop, cache or claim of atomicity. Later operations must read afresh before/after their separately authorized mutations.

## Isolation and verification boundary

The existing diagnostic/control readers retain their policies: diagnostic desktop-zero fallback, strict current control evidence without a desktop-count dependency, and existing current-entry workarea parsing. The old current parser was extracted mechanically for regression tests, preserving warning/error behavior. `main.rs` changes are test fixtures and regression assertions only. Visibility classification, protocol v2, command execution guards, deadlines and scheduling are unchanged. Bring Here/Recover remain Unsupported.

Deterministic/injected tests cover strict property metadata and absence, count/target/current boundaries, checked lengths, multi-desktop target selection, signed root coordinates, workarea/viewport compatibility, monitor identity/equality, body fit, stale snapshots and exact read/no-retry behavior. Regression tests cover legacy diagnostic/control/workarea policies and ensure the two new atoms do not interrupt existing movement/layer/visibility processing. Existing visibility and Stage-A Unsupported tests remain unchanged.

Local verification passed `cargo fmt --check`, `cargo build`, `cargo clippy --all-targets -- -D warnings` and `cargo test`, each using `--manifest-path experiments/desktop-probe/Cargo.toml` from the repository root. The suite reports **537 passed, 0 failed**: 47 destination tests and two legacy-layout regressions added to the accepted 488-test foundation. This is deterministic/injected evidence, separate from matching CI and independent review.

No H0/native host test, workspace mutation, WM transport helper, body move/map/unmap/resize/restack/layer change, focus/activation request, host configuration edit or Bring Here/Recover execution is part of this candidate. Automated evidence does not establish native Openbox relocation behavior. H0 and Stage C require separate authorization.
